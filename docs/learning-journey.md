# Последовательная учебная программа

Источник: схема пользователя от 21.10.2026 и предоставленные программы двух траекторий. Ссылки и файлы учебного контента не публикуются в репозитории.

Последняя схема содержит две траектории, по три модуля и сертификат на 72 часа. В старом текстовом ТЗ есть несовпадающие варианты 36 часов и пяти модулей. Количество модулей и часы хранятся в настройках курса, а не зашиты в интерфейсе.

## Учебный путь

1. Регистрация аккаунта. Старый API с learning_track также поддерживается.
2. Выбор опубликованной активной траектории в личном кабинете.
3. Последовательное прохождение материалов модуля и итогового теста.
4. Получение сертификата, PDF и QR-кода после завершения всей программы.

В настройках курса включите certificate_enabled, задайте certificate_hours=72 и certificate_module_count=3. При включении сервер закрывает последующие модули. Необходимо опубликовать ровно заданное число модулей; в каждом нужны материалы и один итоговый тест с вопросами. Неполная программа не даёт сертификат. Существующие курсы по умолчанию не меняют режим работы.

Обычная программа использует passing_percent теста. Если у курса также включён adaptive_learning_enabled, сохраняется существующая методика оценки готовности: успешность итогового тестирования определяется ею. Дополнительный конфликтующий порог по проценту не вводится. Обход последовательности через прямую ссылку или API запрещён.

## API

- GET /api/v1/courses/{slug-or-short-id}/journey/
- POST /api/v1/courses/{slug-or-short-id}/certificate/ - выдача владельцу учебных результатов, идемпотентно.
- GET /api/v1/certificates/{uuid}/ - проверка документа по непредсказуемой ссылке.
- GET /api/v1/certificates/{uuid}/download/ - настоящий PDF.
- GET /api/v1/certificates/{uuid}/qr/ - PNG QR-кода.

Выдача сохраняет имя, название курса/траектории и часы на момент завершения. QR-код предназначен для передачи сертификата: обладатель ссылки видит имя и сведения о прохождении, но не email, профиль, ответы и учебные работы. Обычного публичного списка сертификатов нет. Аннулирование доступно в Django Admin; аннулированный документ не скачивается. Сертификат платформы не содержит фиктивных подписей, печатей или заявлений о государственной аккредитации.

## Тьютор

Тьютор находится в LearningLayout рядом с лекцией или практикой, на узком экране открывается панелью поверх текущего материала. Отдельной страницы тьютора нет. Для практики контекст собирается на сервере из опубликованной версии задания, критериев и собственной рабочей области студента. Черновики, чужие документы и ключи тестов не передаются. При смене материала диалог и голосовая сессия переключаются на новый context_id. Во время тестирования тьютор скрыт и недоступен через API контекста теста.

## Развёртывание

Сначала backend: requirements.txt, шрифт DejaVu Sans в образе и python manage.py migrate (0019, только новые поля и таблица). Затем frontend. PUBLIC_SITE_URL должен содержать реальный адрес платформы; по умолчанию https://aiedu.com.kz. CERTIFICATE_FONT_PATH позволяет явно выбрать Unicode TTF. Настройки курсов включаются администратором после проверки структуры, существующие материалы автоматически не удаляются и не переносятся.

Полная загрузка и сверка лекций, практик и ключей тестов из Drive является отдельной операцией с данными. Этот код не выдаёт демонстрационные фрагменты за полный утверждённый курс и не публикует материалы Drive в GitHub. Локальный сценарий проверки находится вне репозиториев, в E:/eduai/ops/journey-preview, с отдельной синтетической базой.
